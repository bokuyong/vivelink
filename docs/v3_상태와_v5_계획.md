# v3 상태와 v5 계획

## v3에서 확인한 문제

1. 음성 명령 해석이 실제로는 없었다.
2. 고정된 토스 송금만 수행하도록 설계되어 있었다.
3. 수동 IP 입력과 ADB over Wi‑Fi 의존성이 강했다.
4. 기기 수가 늘어나는 구조를 고려하지 않았다.
5. UI가 기능 대비 복잡했고 이미지 리소스도 포함되어 있었다.

## 이번에 반영한 방향

1. sender는 한 개만 유지하고 음성 전송기 역할로 단순화했다.
2. controller는 자연어 명령 실행기 역할로 바꿨다.
3. 기기 자동 발견을 넣어 수동 IP 의존을 줄였다.
4. controller를 3개 기기 flavor로 빌드되게 만들었다.
5. 앱 실행과 기본 접근성 제어를 우선 지원하도록 했다.

## 현재 기준 판단

### 가능

- 특정 앱 실행
- 기본 화면 제어
- 간단한 클릭/입력/스크롤
- 기기별 컨트롤 앱 분리

### 조건부 가능

- 더 많은 명령 해석
- 앱별 워크플로우 자동화
- 기기별 맞춤 보정

### 현재 불가능

- 모든 자연어를 완전 정확하게 해석
- 모든 앱에서 무제한 자동화
- Miracast만으로 제어 채널까지 대체
